# Historical UTM Migration and Coexistence

V2 is a forward-control system. It prevents new drift; it does not make historical UTMs correct by relabeling them. Historical analysis therefore uses a confidence-scored crosswalk that preserves the raw evidence.

## Effective-date policy

Set a production effective timestamp. Records issued by V2 at or after that time are `governed_v2`. Older or independently created URLs are `legacy` or `unregistered` unless there is direct registry evidence. Never infer that a well-formatted URL was generated by V2.

## Non-negotiable rules

- Keep raw UTM values, landing URL, event/session timestamp, platform click IDs, and source record identifiers unchanged.
- Add normalized and mapped columns beside raw columns; do not overwrite history.
- Never manufacture an `rpc_`, `rpi_`, or `rpl_` identifier for an old touch unless a documented one-to-one source mapping proves it.
- Prefer `unmapped` over a confident-looking but ambiguous attribution.
- Time-bound mappings when a legacy name changed meaning.
- Preserve who approved each mapping, its evidence, confidence, and effective dates.

## Discovery inventory

Profile at least 12–18 months of GA4, PostHog, Snowflake marketing-touch data, active ad-platform destinations, HubSpot campaigns, and any existing UTM sheets/builders. Summarize each raw combination by first/last seen, volume, conversion/pipeline contribution, landing domain, and platform identifiers.

## Crosswalk model

Create a governed Snowflake table such as `GOVERNANCE.LEGACY_UTM_CROSSWALK`:

| Column | Meaning |
|---|---|
| `mapping_id` | Immutable crosswalk record ID |
| `raw_source`, `raw_medium`, `raw_campaign`, `raw_content`, `raw_term` | Exact observed values; nullable only when absent |
| `source_system` | GA4, PostHog, ad platform, HubSpot, or other origin |
| `valid_from`, `valid_to` | Time range in which the mapping is valid |
| `mapped_campaign_id`, `mapped_initiative_id` | Governed IDs when evidence supports the relationship |
| `normalized_source`, `normalized_medium` | Governed taxonomy values for analysis |
| `confidence` | `exact`, `high`, `medium`, `low`, or `unmapped` |
| `evidence` | Human-readable basis and source references |
| `approved_by`, `approved_at` | Accountability |

Confidence guidance:

- `exact`: an authoritative external ID or archived registry proves one-to-one identity;
- `high`: consistent name, dates, destination, and platform account support one candidate;
- `medium`: likely match but one significant attribute is missing;
- `low`: heuristic only; exclude from default attribution reporting;
- `unmapped`: no defensible match.

Default Mode models may include `exact` and `high`; show `medium` separately and exclude `low`/`unmapped` unless the report explicitly studies data quality.

## Coexistence in Snowflake

The conformed touch model should retain:

- `raw_*` columns exactly as received;
- `observed_utm_id` from the URL/event when present;
- `resolved_campaign_id` and `resolved_initiative_id` from either an exact V2 registry join or approved legacy mapping;
- `governance_status`: `governed_v2`, `legacy_mapped`, `legacy_unmapped`, `unregistered`, or `invalid_id`;
- `mapping_confidence` and `mapping_id` for explainability.

Resolution order is strict: valid observed `utm_id` → registry campaign snapshot → approved historical crosswalk. Human-readable `utm_campaign` substring matching is never the first join path.

## Active-link remediation

For legacy links still serving traffic:

1. inventory and rank by spend/traffic;
2. issue a V2 replacement through the registry;
3. test the destination and platform macro behavior;
4. update the platform during an approved change window;
5. retain old and new values in the crosswalk with a cutover timestamp;
6. verify GA4/PostHog capture and Snowflake joins after launch.

Do not edit expired assets merely to make historical reports look clean.

## Migration acceptance checks

- 100% of raw values retained and reproducible from the source load;
- 100% of crosswalk rows have confidence, evidence, approver, and effective dates;
- zero `rpc_` values join to more than one campaign;
- all high-spend active legacy links have a remediation owner;
- Mode reports visibly distinguish governed, mapped legacy, and unmapped traffic;
- mapping changes are versioned and re-runnable without changing prior raw data.
